모델

Google, Gemini 4
Argon 발표

Google이 개발·분석 업무와 보안 점검을 위한 Gemini 4 Argon을 발표했습니다. 여러 단계의 작업을 오래 이어 가도록 설계한 모델입니다.

Google 내부에서는 Argon 에이전트가 영상 디코더 libgav1의 Rust 코드를 반복적으로 시험하고 개선했습니다. Google에 따르면 같은 영상을 출력하면서 기존 Rust 구현보다 2.7배 빠르게 실행됐습니다.

보안 업체 Wiz의 활용 사례도 소개했습니다. Argon이 병원용 소프트웨어에서 민감한 개인정보를 노출하는 취약점을 발견했다는 설명입니다.

다만 현재는 사이버 공격 방어를 맡는 일부 보안 담당자에게 먼저 제공합니다. Google은 일반 공개에 앞서 악용 방지와 프롬프트 인젝션 대응 등 안전장치를 보강하고 있습니다.

이들의 피드백을 반영한 뒤, 유료 API 고객과 Google AI Ultra 구독자부터 제공 범위를 넓힐 예정입니다.

도구·업무 환경

Claude, Google
Docs·Sheets·Slides 안에서 직접 편집

Anthropic이 Google Docs·Sheets·Slides에서 Claude를 사용할 수 있는 부가 기능을 공개했습니다. 모든 유료 Claude 요금제에 공개 베타로 제공됩니다.

파일 옆에 Claude 대화창을 열면 현재 파일과 선택한 글·셀·슬라이드를 읽습니다. 다른 앱으로 옮겨 가지 않고 작업 중인 파일에 수정 내용을 직접 반영할 수 있습니다.

가령 Docs에서 제품 요구사항 문서의 요약을 줄이고, 다음 할 일을 표로 정리해 달라고 요청할 수 있습니다. 문장이나 제목을 고칠 때는 주변 서식을 유지합니다.

기본 설정에서는 Claude가 수정할 내용을 보여 주고, 사용자가 승인하면 적용합니다. 모든 수정을 허용하도록 설정하면 중간마다 멈추지 않고 작업을 이어 갑니다.

반복하는 작업의 형식과 절차는 스킬로 저장해 재사용할 수 있습니다. 예를 들어 발표 자료를 만드는 방식을 저장해 두면, 팀이 다음 자료도 같은 방식으로 만들게 할 수 있습니다.

Claude Code v2.1.292
업데이트

Anthropic이 Claude Code v2.1.292를 배포했습니다. 답변 표시와 입력 복구를 개선하고, 하위 에이전트의 실행 설정을 추가했습니다.

긴 글머리표나 번호 목록을 답변으로 표시하는 속도가 빨라졌습니다. 답변이 출력되는 도중뿐 아니라 창 크기를 바꾸거나 Ctrl+O로 대화 기록을 다시 펼칠 때도 적용됩니다.

Ctrl+C로 지운 입력의 복구가 개선됐습니다. 중간에 다른 메시지를 보내거나 슬래시 명령을 실행해도, 지웠던 입력을 ↑로 다시 불러올 수 있습니다.

/resume이나 세션 선택 화면으로 이전 작업을 이어 갈 때 Plan Mode가 복원되지 않던 문제도 고쳤습니다.

하위 에이전트에게 일을 맡길 때도 원하는 effort 수준을 지정할 수 있습니다. Agent 도구에 이를 전달하는 항목이 추가됐습니다.

Section 206 — 13
도구·업무 환경

Claude Code Mods 공개

Anthropic이 Claude Code의 화면과 동작을 바꾸는 Mods를 공개했습니다. 플러그인에 담아 설치하며 CLI와 데스크톱 앱에서 쓸 수 있습니다.

Mod는 도구 호출 같은 이벤트가 발생할 때 실행되는 TypeScript 함수입니다. 도구 실행을 막거나 바꾸는 등 작업 과정에 직접 개입할 수 있습니다. 도구 결과에 담긴 비밀 정보를 Claude가 읽기 전에 가리는 것도 가능합니다.

화면도 바꿀 수 있습니다. 대화 옆에 CI/CD 상태를 띄우고, 빌드 성공·실패에 맞춰 갱신하는 식입니다. 필요한 버튼이나 입력창을 붙일 수도 있습니다.

원하는 기능을 Claude Code에 설명하면 Mod의 코드 작성과 설치, 현재 세션에 적용하는 과정까지 맡길 수 있습니다.

Mods는 Claude Code와 같은 컴퓨터 접근 권한으로 실행되며 별도로 격리되지 않습니다. Anthropic은 신뢰하는 출처의 코드만 설치하라고 설명합니다.

Claude Code Mods
활용 예제와 설치 방법

Claude Code의 공식 문서는 Mods로 만들 수 있는 기능과 설치 방법을 소개합니다. 실제 코드를 받아 실행해 볼 수 있는 예제도 함께 제공합니다.

예제 Mod인 blast-radius는 rm -rf나 force push 같은 명령을 실행하기 전에 멈춥니다. 무엇이 바뀔지 보여 주고, 사용자가 실행하거나 취소하도록 버튼을 제공합니다.

또 다른 예제인 replay-theater는 /replay 명령을 추가합니다. Claude가 지난 작업에서 수정한 파일들을 단계별로 되짚어 볼 수 있습니다.

이 예제들은 코드를 받아 직접 실행해 볼 수 있는 완성된 플러그인입니다. 예제 저장소를 복제한 뒤, Claude Code를 시작할 때 --plugin-dir로 해당 예제 폴더를 지정하면 한 세션에서 시험할 수 있습니다.

자세한 내용은 원문에서 확인해 보세요.

도구·업무 환경

Muse Gadget SDK,
직접 만든 기기를 Muse에 연결

Meta가 Muse에 화면·센서 같은 하드웨어를 연결하는 SDK와 펌웨어를 오픈소스로 공개했습니다. 직접 만든 기기를 iOS·Android의 Muse 앱과 연결해 쓰는 방식입니다.

예를 들어 쓰지 않는 Raspberry Pi나 Linux 컴퓨터에 SDK를 설치하고 필요한 명령을 추가하면, Muse에 시스템 관리나 Home Assistant 설정 관리를 맡길 수 있습니다.

ESP32 보드로는 화면에 이미지를 표시하거나 음성을 주고받는 기기를 만들 수 있습니다. 버튼과 센서 등도 연결해 기기가 할 수 있는 일을 구성합니다.

기기를 Muse 앱과 연결하려면 기기별 SDK 토큰을 발급받고 앱에서 개발자 모드를 켜야 합니다.

저장소에는 ESP32와 Linux용 SDK가 각각 공개돼 있습니다. 사용할 기기에 맞는 README에서 시작 방법을 확인할 수 있습니다.

에이전트 활용

Opus 5.5에 긴 작업을 맡기는 방법

Anthropic의 Opus 5.5 활용 가이드입니다. 질문하는 방법부터 Claude Code에서 긴 작업을 이어 가고 결과를 확인하는 방법까지, 상황별 지시문을 함께 소개합니다.

긴 작업을 맡길 때는 무엇을 완료해야 하고, 언제 멈춰 물어봐야 하는지를 함께 전달하라고 제안합니다.

결제 API를 새 클라이언트로 옮기는 예시에서는 모든 API의 전환, 기존 클라이언트 삭제, 테스트 통과를 완료 조건으로 줍니다. 이유를 설명할 수 없는 테스트 실패가 생기면 멈추고 물어보게 합니다.

작업 도중 “계속할까요?”라며 멈추는 경우에는 CLAUDE.md에 진행 기준을 적도록 안내합니다. 사용자 판단이 필요 없는 단계는 이어 가되, 데이터 삭제처럼 되돌리기 어려운 작업 전에는 확인을 받게 하는 식입니다.

작업 목록 관리와 결과 검토에 쓸 수 있는 지시문도 담겨 있습니다. 자세한 내용은 원문에서 확인해 보세요.

Claude의 effort를 높이면
무엇이 달라질까

Anthropic의 Thariq Shihipar가 Claude의 계산량을 조절하는 effort 설정을 비교했습니다. 앱 제작 실험과 벤치마크 분석으로 설정에 따라 작업 방식이 어떻게 달라지는지 살펴봅니다.

기능을 자세히 지정하지 않고 운동 기록 앱을 요청하자, 낮은 effort에서는 기록과 간단한 그래프가 나왔습니다. 설정을 높일수록 기능이 늘었고, 최대 설정에서는 히트맵까지 추가됐습니다.

어떤 기능을 넣을지 Claude가 스스로 결정한 것입니다. 저자는 높은 effort에서 사용자가 정하지 않은 부분을 모델이 대신 판단하는 일도 늘어난다고 설명합니다.

반대로 Claude와 문답하며 요구사항을 먼저 자세히 정리하자, 모델과 effort 설정이 달라도 디자인과 구현이 서로 비슷해졌습니다. 세부 차이는 남았지만 결과의 큰 차이는 줄었습니다.

원문은 버그 수정과 보안 검증에서 effort가 만드는 차이도 다룹니다. 저자가 빠르게 구현하고 고치는 단계와 충분히 검증하는 단계에서 설정을 어떻게 나눠 쓰는지도 확인해 보세요.

서비스 생태계·접근 권한

앱에서 에이전트로, 사용자와 만나는
창구의 변화

Ben Thompson이 AI 에이전트가 앱과 서비스의 역할을 어떻게 바꿀지 분석했습니다. 직접 Muse에 요리법 정리를 맡긴 경험에서 출발합니다.

Instagram에 저장한 요리법을 정리해 달라고 하자 처음에는 PDF가 나왔습니다. 더 쓰기 편한 형태를 요청하니 자신만의 앱을 얻었습니다. 아직 저장한 영상을 분류하는 수준이었지만, 필요한 화면을 대화로 만들어 낸 것입니다.

사용자는 원하는 일을 하려고 앱마다 사용법을 익혀 왔습니다. Thompson은 에이전트가 앱을 대신 조작하고 필요한 화면까지 만들어 주면, 개별 서비스를 직접 다룰 필요가 줄어든다고 봅니다.

사용자는 에이전트에 일을 맡기고, 기존 앱과 서비스는 그 뒤에서 일을 처리하는 공급자가 된다는 설명입니다. 사용자와 직접 만나는 창구를 에이전트가 차지하는 변화입니다.

그렇다면 사람들이 일을 맡길 에이전트는 누가 제공하게 될까요? Thompson은 이미 많은 소비자가 쓰는 서비스를 가진 Meta와, 직장에서 널리 쓰이는 업무 도구를 가진 Microsoft에 주목합니다. 기존 사용자에게 각각 Muse와 Copilot을 연결할 수 있다는 점을 강점으로 봅니다.

Section 412 — 13
서비스 생태계·접근 권한

AI 에이전트를 웹사이트가 받아들일 조건

TechCrunch가 AI 에이전트의 쇼핑·예약을 막는 웹사이트의 접근 정책과 인증 문제를 취재했습니다. 사용자가 일을 맡겨도, 사이트에서 받아들이지 않으면 에이전트는 요청을 끝낼 수 없습니다.

기업마다 접근을 허용하는 범위가 다릅니다. Amazon은 Meta의 Muse를 차단했습니다. eBay는 AI를 통한 구매를 일괄 금지하지는 않지만, 허가받지 않은 에이전트의 접근이나 자동 데이터 수집 등은 제한한다고 밝혔습니다.

접근을 허용해도 기존 봇 방지 장치에 걸릴 수 있습니다. 스팸과 악의적인 자동화 활동을 막는 장치가 사용자의 구매를 대신하는 에이전트까지 막는 것입니다.

Muse와 제휴한 Walmart에서도 구매 실패가 보고됐습니다. Walmart는 의도적인 차단이 아니라고 답했고, 기사는 사람 확인 절차가 중간에 끊기면서 인증에 실패했을 가능성을 짚습니다.

Meta·Walmart·Stripe 등은 사용자가 맡긴 요청을 수행하는 에이전트와 악성 봇을 구분하고, 온라인 상거래에서 기업과 소통할 공개 표준을 개발하고 있습니다.

기사는 개별 기업과의 제휴도 해법으로 봅니다. 에이전트의 접근을 허용하기로 합의한 사이트라면, 접속 실패를 제휴한 기업들이 해결할 기술 문제로 다룰 수 있다는 설명입니다.
