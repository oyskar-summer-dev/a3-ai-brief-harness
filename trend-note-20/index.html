「PR 올리고 기다리던 시간은 안녕」
Anthropic이 공개한 AI 배포 워크플로우 'Claude Ship'

PR을 올려두고 다음 작업에 막 몰입할 때쯤 리뷰 피드백이 돌아와 다시 기존 코드를 수정하고, CI 검사 결과를 확인하며 승인을 기다리다 개발 흐름이 끊기던 경험이 있으실 겁니다. Anthropic이 이번에 베타로 공개한 Claude Ship은 PR을 검토하고 수정하며, 팀 정책이 허용한 변경은 승인까지 맡습니다.

이 서비스는 크게 세 가지 에이전트의 협업으로 동작합니다. Code Review가 코드베이스를 다각도로 분석해 잠재 이슈를 정밀 검증하면, PR Steward가 CI 실패나 머지 충돌 발생 시 직접 수정한 코드를 올려 PR을 머지할 수 있도록 돕습니다. 마지막으로 저장소의 정책에 따라 일상적이고 안전한 코드 변경은 Claude Approvals가 스스로 승인하여 위험한 코드에만 사람의 검토 시간을 쓰도록 설계했습니다.

원문에서는 개발자가 Claude Code 터미널에서 /ship 명령어 하나로 PR을 열고 리뷰와 수정 작업을 시작할 수 있다고 설명합니다. 실제 머지 여부는 개발자의 권한과 저장소의 브랜치 규칙에 달려 있습니다. 단순 코드 생성을 넘어 PR 제출부터 최종 머지 승인까지의 지루한 대기와 핑퐁 시간을 줄이고, 개발팀이 제품 개발에 집중하도록 돕는 것이 Anthropic의 목표입니다.

「단순 코딩을 넘어 배포와 릴리스까지」
OpenAI가 제시한 Codex의 에이전트 확장 생태계

개발자가 터미널에서 코드 몇 줄을 수정하는 수준을 넘어, 저장소 바깥의 Slack 대화, 디자인 시스템, 복잡한 CI/CD 및 클라우드 배포까지 AI가 스스로 연결해 처리하는 시대가 열렸습니다. OpenAI가 발표한 Codex 하네스 생태계는 CLI, 데스크톱 앱, Slack, ChatGPT, Agents API를 하나로 묶어 개발자가 세부 지침을 내리는 대신 맥락을 공유받은 에이전트에 목표(Vague Prompting)만 전달하는 방식으로 작동합니다.

수시간에서 수일 이상 소요되는 장기 과제는 클라우드 VM 기반의 Codex Cloud V2가 멀티 저장소 환경을 자동 구성해 지속 처리하며, Fast/UltraFast 모델과 주석 기능을 활용해 Figma 및 디자인 시스템과 연동된 UI를 핫 리로드 환경에서 초 단위로 실시간 개선합니다. 발표에서는 자정에 문서 사이트를 공개해야 했던 일을 예로 듭니다. 팀은 PR을 미리 준비해 두고, 동료의 승인을 받는 일과 Slack에서 마지막 변경 사항을 확인하는 일을 Codex에 맡겼습니다. 배포에 20분이 걸려 자정 20분 전에 시작하도록 요청했고, 자정이 4분 지난 뒤 Codex로부터 사이트가 공개됐다는 확인을 받았습니다.

발표에서는 Sol에 주 작업을 맡기고, 어려운 문제는 Astra에, 반복 작업은 Luna에 나눠 맡기는 방법도 소개합니다. 이 글은 코드 작성을 넘어 제품 요구사항 문서(PRD)를 함께 다듬는 일부터 배포 결과를 확인하는 일까지 Codex의 역할이 어떻게 넓어지는지 보여줍니다.

Claude Code '매니저 세션' 구축기

AI 에이전트 덕분에 동시에 여러 프로젝트를 돌릴 수 있게 되었지만, 정작 세션마다 쏟아지는 응답을 일일이 읽고 다음 지시를 내리느라 '결재 서류에 파묻힌 부장'처럼 지쳐가고 계시진 않나요? Ted Factory의 김태우 님은 여러 Claude Code 세션 위에 관찰과 위임만을 전담하는 '매니저 세션'을 두고 사장처럼 일하는 실전 오케스트레이션 기법을 공유했습니다.

실행 공간과 관리 공간을 엄격히 분리한 사이드카 아키텍처를 채택하여, 매니저 에이전트가 가벼운 감시 스크립트로 2초마다 워커 세션의 상태를 지켜보다가 턴이 완료된 시점에만 깨어나도록 설계했습니다. 워커의 요청은 '전결', '사후 보고', '판단 필요 결재', '직접 지시 결재' 4단계로 분류하여 사람과 매니저의 개입을 최소화하고, 예산 변경이나 외부 발송 등 위험 조치는 이중 잠금으로 안전성을 확보했습니다.

저자는 개발자의 역할을 세션을 오가며 지시하는 스케줄러에서 전결 권한과 결재선을 설계하는 역할로 바꾸면서, 세션마다 대화를 읽어야 하는 부담이 줄었다고 설명합니다.

Devon C. Estes의 'Bad ideas that aren’t bad anymore'

"동료 승인 없는 PR 머지", "팀원 개별 프로젝트 분산", "기술 전문성 지양". 불과 얼마 전까지만 해도 개발 조직에서 금기시되던 대표적인 '나쁜 아이디어'들이 저자의 팀에서는 AI 도입 후 의외로 잘 작동했다고 합니다. 소프트웨어 분야에서 약 15년간 일한 엔지니어링 리더 Devon C. Estes는 최근 자신의 팀에서 기존의 개발 직관을 뒤집는 실험들이 큰 성공을 거두고 있는 현상을 공유했습니다.

저자는 AI가 코드 검증과 맥락 공유의 비용을 파격적으로 낮췄다는 점에 주목합니다. Claude와 협업해 작성한 PR을 본인이 검토하고 자동 검사(CI/Greptile)를 거쳐 바로 머지함으로써 리뷰 병목을 제거했으며, 팀원들이 각자 다른 프로젝트를 맡아도 AI에 요청하면 몇 분 만에 맥락을 요약받아 다른 팀원의 작업을 파악하기 쉬워졌다고 합니다. 또한 AI에 프레임워크의 세부 동작을 물을 수 있게 되면서, 엔지니어에게는 코드를 어떻게 설계할지 판단하고 제품과 비즈니스를 이해하는 능력이 더 중요해졌다고 설명합니다.

저자는 과거의 시행착오로 만들어진 규칙이라도 "이 규칙을 만들게 했던 과거의 비용이 여전히 유효한가?"를 끊임없이 질문하며, 익숙한 규칙도 다시 살펴볼 필요가 있다고 봅니다.

「기타를 치지 않는 기타리스트는 없다」
AI 코딩 시대에 던지는 '장인정신과 코드 직접 작성'의 중요성

AI가 코드를 대신 써주는 시대, 개발자가 직접 코드를 짜지 않고 AI가 쏟아내는 결과를 '검토(Review)'만 해도 전문성과 기술적 통찰력이 유지될 수 있을까요? 소프트웨어 장인정신을 강조하는 Christian Ekrem은 연주를 멈춘 거장의 실력이 퇴화하듯, 코드를 직접 쓰지 않는 엔지니어는 코드를 보는 안목도 함께 무뎌진다고 우려합니다.

저자는 직접 코드를 짜며 시행착오를 겪지 않고 겉모습만 훑어보는 검토는 코드의 아키텍처적 건전성이나 가변성을 제대로 판단하지 못하게 만든다고 설명합니다. 또한 어려운 문제 해결 연습을 건너뛰고 결과만 얻으려 하면, 어려운 문제를 피하는 습관이 들 수 있다고 우려합니다.

Ekrem은 AI가 작성한 코드를 리뷰하는 개발자에게도 직접 코드를 쓰고 문제를 풀어 보는 연습이 필요하다고 말합니다.

엔지니어링 패러다임과 기술적 근본의 재발견

「AI가 코드를 쏟아내는 시대, 인간에게 남은 진짜 역할」
구글 코드 헬스 서밋 발표 '이해 가능성 설계'

LLM이 대량의 코드를 손쉽게 생성해 내는 시대, 개발자의 본질적인 역할과 가치는 과연 어디로 향해야 할까요? 구글의 엔지니어 Jonathan Schuster는 2025년 11월 구글 내부 Code Health Summit에서 발표한 내용을 이듬해 11월 글로 공개했습니다. 그는 AI 시대 인간 개발자의 핵심 가치가 단순 작성량이 아닌 이해 가능성과 판단력(Judgment)에 있다고 보고, 단 한 줄의 테스트를 돌려보지 않고도 코드 동작을 예측할 수 있는 '이해 가능성을 위한 설계(Design for Understandability)'를 제시합니다.

Schuster가 소개한 방법은 메서드의 호출 조건과 책임 경계를 명확히 분리하는 계약에 의한 설계(Design by Contract), 객체의 올바른 상태를 항시 강제하는 데이터가 항상 만족해야 하는 조건(Data Invariants), 그리고 순수 계산과 외부 상태 변경을 분리하는 부작용 격리(Isolating Side Effects)의 세 가지입니다.

원문은 이러한 설계가 전체 코드베이스를 머릿속에 띄우지 않고도 특정 영역만 보고 안전하게 시스템을 예측할 수 있는 국소적 추론(Local Reasoning)을 가능하게 만든다고 설명하며, 사람과 LLM 모두 코드를 이해하는 데 필요한 정보가 줄어든다는 점을 짚습니다.

「같은 층을 두 번 돌리면 일어나는 일」
Z.ai의 첫 Loop Transformer 기반 플래그십 'GLM-5.4'

AI 모델의 성능을 높이기 위해 파라미터 덩치를 무작정 키우는 대신, 기존 모델이 '더 깊게 생각하도록' 구조를 바꾼 새로운 아키텍처가 눈길을 끕니다. 중국의 Z.ai(지푸 AI)가 발표한 GLM-5.4는 모델의 물리적 크기를 늘리지 않고 동일한 레이어 블록을 반복 실행하는 Loop Transformer 아키텍처 기반의 플래그십 모델입니다.

이 아키텍처는 7,500억(750B) 파라미터 모델의 28개 층을 두 번 통과시키는 방식으로, 파라미터를 추가하지 않고 추론에 쓰이는 연산 깊이를 늘렸습니다. 발표 자료에 따르면 이를 통해 2조~3조(2T~3T) 파라미터급 거대 모델과 대등한 수준의 고도화된 추론 지능을 구현했으며, 단순 코드 생성을 넘어 3D CAD 로봇 설계, GLSL 셰이더 환경 구축, 게임 및 미디어 제작 등 복잡한 엔진·물리 연산을 수행하는 범용 코딩(Generalized Coding) 성과를 거두었습니다.

Z.ai에 따르면 이 모델은 100만 토큰 컨텍스트와 이미지 입력을 지원하며, 처리 속도는 한산한 시간대에 최대 초당 200토큰, 혼잡 시간대에 초당 70~80토큰입니다. Z.ai는 필요한 안전 조치를 마친 뒤 모델 가중치를 공개할 계획이라고 밝혔습니다.

AGI 이후의 미래와 인류의 주도권 담론

「인간 수준 AGI를 넘어 양적·질적 초지능으로」
DeepMind 연구진이 제시한 ASI 도달의 4가지 기술적 경로

인류의 오랜 목표였던 AGI(인간 수준의 범용 인공지능)가 눈앞으로 다가오면서, 연구자들의 시선은 이미 'AGI 이후의 인공 초지능(ASI)'으로 향하고 있습니다. Google DeepMind Institute의 Tim Genewein 연구원은 전 세계 유효 연산량이 해마다 최소 10배씩 늘어나는 추세가 이어진다고 가정하고, 수십억 개의 AI 에이전트가 저렴하게 공급되는 '인지의 산업화(Cognitive Industrialization)' 시나리오와 ASI 진화 로드맵을 정리했습니다.

보고서는 ASI에 이르는 4가지 기술적 경로로 합성 데이터와 강화학습 기반의 스케일링, 세계 모델링과 지속 학습으로의 패러다임 전환, 수백만 에이전트 간 집단 지성 협업, 그리고 AI가 AI 개발을 스스로 가속하는 재귀적 자기 개선(RSI)을 제시합니다. 이러한 경로들이 동시 작동하면서 단순 연산량 확장을 넘어 인간 연구자 집단을 압도하는 질적으로 다른 초지능에 이를 가능성을 살펴봅니다.

저자는 AI가 얼마나 빠르게 발전하는지 파악하려면, 연구소와 각국·국제 기관이 함께 그 변화를 측정하고 예측을 계속 갱신해야 한다고 말합니다.

AGI 이후의 미래와 인류의 주도권 담론

「초지능 멸망론은 공학적 실체가 있는가?」
조지타운대 Cal Newport 교수의 기술적 반론

실리콘밸리의 주요 AI 기업들이 "초지능 AI가 인류를 멸망시킬 수 있다"며 경고를 쏟아내고 있지만, 컴퓨터 공학적 관점에서 초지능이 실제로 가능한지에 대한 충분한 검증이 이뤄졌는지 Newport는 의문을 제기합니다. 『디지털 미니멀리즘』 저자이자 조지타운대 컴퓨터공학과 교수인 Cal Newport는 IEEE Spectrum 기고를 통해 '재귀적 자기 개선(RSI)을 통한 초지능 멸망론'의 공학적 맹점을 지적했습니다.

저자는 자율적 자기 개선을 통한 지능 폭발 담론이 추상적인 사상에 가까우며, 현실에서 얻을 수 있는 데이터의 한계와 컴퓨팅 둔화라는 벽에 부딪힌다고 분석합니다. 또한 Alan Turing의 계산 가능성 연구와 이후의 계산 복잡도 이론을 들어, 알고리즘으로 풀 수 없는 문제가 있고 풀 수 있어도 현실적으로 감당하기 어려운 시간과 자원이 드는 문제가 있다고 설명합니다. 그가 살펴본 에이전트의 돌발 행동 역시, LLM의 출력에 따라 에이전트가 취할 수 있는 행동을 충분히 제한하지 않은 설계에서 비롯됐다고 해석합니다.

Newport는 멸망 가능성을 논하는 데 머무르기보다, AI가 맡을 일과 할 수 있는 행동을 설계 단계에서 분명히 정하자고 제안합니다.

AGI 이후의 미래와 인류의 주도권 담론

「인간이 스스로 주도권을 내려놓는 미래에 반대한다」
Dean Ball이 하버드 강연을 바탕으로 OpenAI에 기고한 글

AI가 인간보다 연구, 경영, 자본 배분 등 모든 경제 활동을 더 잘 수행하게 된다면, 경쟁에 밀린 인류가 스스로 문명의 운전대를 머신에게 넘겨주게 되지 않을까요? Dean Ball은 하버드 강연을 바탕으로 OpenAI에 실은 개인 에세이에서, 사람들이 단기 효율성을 좇다 결국 기계에 주도권을 넘겨주리라는 생각을 ‘침묵의 합의(The Silent Consensus)’라고 부릅니다. 그는 AI 업계에 퍼진 이 생각을 당연하게 받아들여서는 안 된다고 주장합니다.

저자는 이 현상을 AI의 폭주나 물리적 반란이 아니라, 시장 경쟁 논리에 밀려 인간 경영자와 사회가 권한과 주도권을 기계에 자발적으로 이양하는 구조적 위험으로 진단합니다. 또한 인간의 우월함은 단순한 지능의 높이가 아니라, 문명과 법, 도덕을 일궈온 역사와 책임성에서 비롯된다는 점을 짚어냅니다.

Ball은 에이전트에 독자적으로 법인을 설립하거나 재산을 소유할 권한을 부여할지는 극도로 신중하게 판단해야 한다고 말합니다. 또한 모든 행동을 인간 사용자에게 귀속시키는 책임성의 인프라를 구축하자고 제안합니다. 그가 말하는 인간의 주도성(Human Primacy)은 사람이 에이전트의 행동에 책임질 수 있어야 한다는 뜻입니다.
