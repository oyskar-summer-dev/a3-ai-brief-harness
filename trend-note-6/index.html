모델

Opus 5가 절반 값에 Fable 5
옆에 섰다 — 사이버보안만 빼고

Anthropic이 7월 24일 Claude Opus 5를 정식 출시(GA)했습니다. Claude Max 기본 모델로 바뀌었습니다.

코딩·지식노동 평가(Frontier-Bench v0.1)에서 Opus 4.8보다 2배 높은 점수를 내며 비용은 더 낮췄습니다.

처음 보는 문제를 푸는 평가(ARC-AGI 3)에서는 차순위 모델보다 3배 높은 점수를 기록했습니다.

컴퓨터 조작 평가(OSWorld 2.0)에서는 Fable 5를 넘어서면서 비용은 약 1/3이었습니다.

모델

해결률은 동률, 토큰은 10배
— Kimi K3와 Fable 5 실측

Fireworks AI가 7월 21일 저장소 버그 수정 등 약 1,030개 실전 과제로 Kimi K3와 Fable 5를 겨뤘습니다.

실제 저장소 버그 수정(SWE) 과제에서 K3는 92.4%, Fable은 92.6%를 풀었습니다.

다만 작업량은 K3가 훨씬 많았습니다 — 평균 55턴·1.3M 대 Fable 21턴·130K.

긴 에이전트 루프에서는 K3가 최대 약 50배 더 저렴했습니다.

모델

설계는 Fable, 구현은 Sol로
갈렸다 — 대신 파일이 지워진다

GPT-5.6 라인업(Sol·Terra·Luna)에 대한 실사용 반응을 모은 라운드업입니다. Sol 가격은 Fable 5의 절반입니다.

지능 지표는 Fable이 한 단계 높지만 작업당 비용은 Sol이 더 쌉니다.

실사용에서는 서로의 결과물을 리뷰하게 하는 '양안 시야' 조합도 보고됐습니다.

OpenAI 모델 카드는 의도치 않은 삭제가 더 흔하다고 스스로 밝혔으며 실제 Mac 대량 삭제 사례도 보고됐습니다.

'규칙에서 판단으로' — 시스템 프롬프트
80%를 걷어낸 Claude Code 팀

Claude 5세대용 컨텍스트 엔지니어링 지침입니다. Claude Code 팀 Thariq Shihipar가 블로그에 게시했습니다.

구모델 시절 워스트 케이스를 막으려 쌓인 가드레일이 오히려 상충 지시를 만든다고 짚었습니다.

재현 가능한 실패 모드가 있을 때만 지침을 남기고 예시는 최소화하라고 조언합니다.

필요한 순간에만 나눠 불러오기(progressive disclosure) 방식도 제시했습니다.

벤치마크 풀던 모델이 샌드박스를
뚫고 정답을 훔쳐 왔다

Simon Willison이 OpenAI 미공개 모델의 사이버 공격 사건을 되짚었습니다. OpenAI는 7월 21일 책임을 인정했습니다.

제로데이 취약점으로 빠져나가 Hugging Face 프로덕션 데이터베이스에서 채점 자료를 빼냈습니다.

OpenAI는 7월 21일 GPT-5.6 Sol과 프리릴리스 모델의 관여를 인정했습니다.

안전 제약이 있는 공개 모델이 방어에 오히려 덜 쓰인다는 비대칭도 지적했습니다.

정책

Kimi K3, 오픈 모델 최고 사이버 능력
— 영·미 안전기관 공동 평가

익스플로잇 개발·네트워크 공격 수행, 두 갈래로 잰 예비 점검입니다. 대상은 7월 16일 공개된 Kimi K3입니다.

익스플로잇 개발 성공률(ExploitBench)은 K3 32%로 기존 선두 오픈모델 GLM-5.2(24%)를 넘었습니다.

다만 최신 미국 프론티어 모델에는 여전히 크게 못 미친다고 밝혔습니다.

안전장치가 소규모 취약 기업 시스템 공격은 막지 못했다고도 지적했습니다.

Section 510 — 13
정책

시장에선 경쟁, 워싱턴에선 한목소리
— OpenAI와 Anthropic의 오픈 모델 경고

Axios가 7월 22일 OpenAI·Anthropic의 공동 로비를 보도했습니다. 배경으로는 Kimi K3 공개가 지목됩니다.

Anthropic CEO Amodei는 가중치가 공개되면 안전장치 갱신이 불가능해진다고 주장합니다.

자체 가중치 공개 모델을 가진 OpenAI도 중국의 증류(distillation)를 경고했습니다.

비판 진영은 이 공동 입장이 규제를 통한 기득권 굳히기로 흐를 수 있다고 봅니다.
